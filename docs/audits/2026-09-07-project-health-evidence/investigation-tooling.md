## Proposed target

**justfile (recipe names only):** `setup`, `dev`, `dev-ui`, `gen`, `build`, `test [unit|integration|e2e|all]`, `verify`, `fmt`, `baseline`. Each is one line calling a script; CI, lefthook and agents call the same scripts.

**scripts/ (5 files):**

- `build.sh` — `wails generate module` + `git diff --exit-code frontend/wailsjs` (gen-check), then `wails build` (frontend build is already `wails.json` `frontend:build`). Optional `--platform` for the release matrix.
- `test.sh <unit|integration|e2e|all>` — unit: `go test -race ./...` (no build-in-test) + `jest`; integration: builds `frontend/dist` once, then Go tests that need the embed + `go test -tags native_evidence ./cmd/...`; e2e: builds the native-evidence bundle + binary and runs the scenarios against the **real** backend, then Playwright. - `baseline.sh` — `git rev-parse HEAD`, run `verify.sh` with per-step logs into one directory (e.g. `.baseline/<sha>/`), record exit code + failing test names + lint findings; keep the UNRELIABLE verdict (exit non-zero with zero parsed findings) — the one genuinely valuable idea in the current scripts. `baseline.sh --compare` replaces verify.sh's diff.
