## (B) New findings

**B1. Two full copies of the menu-row primitive inside ShellMenuRow (High).** `ShellMenuRow.module.css:202-266` re-declares `.item/.groupLabel/.separator` that `MenuSurface.module.css:81-183` already owns, then `.fileMenu .item`/`.aboutMenu .item` (`:150-166`) patch `.item` back toward `.row` (border 0, radius 8px, gap 22px). `groupLabel` padding `5px 10px 3px` (`:244`) vs `7px 10px 3px` (`MenuSurface:181`) — the exact drift the MenuSurface header says was fixed. Hover differs (`--surface`+border vs `--hover`).

**B2. The editor context menu is a third design (High; explains owner's observation).** `EditorContextMenu.module.css`: radius `--control-radius` (8px) vs `--popup-radius` (12px), min-width `14rem` vs `250px`, padding `--control-gap` (4px) vs `6px`, row padding `--control-padding` (6px 10px) vs `7px 10px`, no accelerator rendering (`aria-keyshortcuts` only, `EditorContextMenu.tsx:245-249`).

**B3. Tab context menu shadow diverges per theme (Medium).** Only it uses `--context-menu-shadow` (`DocumentTabs.module.css:223`), which Material redefines (`tokens.css:231`); every other popup uses `--win-shadow`.

**B4. Menubar is composed _through_ the appearance controller (High, structural).** `AppearanceControls` owns theme state and renders `settingsMenuRenderer` (`AppearanceControls.tsx:182-188`); production passes `ApplicationShellMenu` → `<ShellMenuRow>` (`App.tsx:237-405, 1990`). The whole menubar is a child prop of a settings widget, which also has an unused fixed-position fallback (`AppearanceControls.module.css:1-6`).

**B5. ShellMenuRow narrow/desktop duplication (High).** File body twice (`:720-779` Radix items vs `:920-972` plain buttons), About twice (`:849-866` vs `:987-999`), Settings/View mounted twice (`:783-813` vs `:1004-1034`), identical 4-call trigger handlers ×4 (`:694-708, 823-837`). ≈150 duplicated JSX lines; element types differ, so keyboard behaviour differs by width.

**B6. ExternalChangePrompt mounted in three places (Medium).** `DocumentTabs.tsx:1345-1350`, `App.tsx:2091-2098`, `App.tsx:2099-2104`; conflict-decision logic duplicated `DocumentTabs.tsx:455-527` and `App.tsx:1713`.

**B7. Dialog chrome ×4, buttons ×3 (Medium).** Overlay/content CSS copied in `ModalShell.module.css:1-30`, `SettingsDialog.module.css:1-25`, `AppearanceDialog.module.css:1-21`, `ShortcutsDialog.module.css:1-24` (max-width 42/32/32/38rem). `.primary/.secondary` in `ModalShell.module.css:71-93` and `SettingsDialog.module.css:66-82` (only the former has focus-visible). Focusable-selector string ×4 (`ModalShell.tsx:12-19`, `ShortcutsDialog.tsx:23`, `SettingsDialog.tsx:35` — different, `AboutDialog.tsx:39`).

**B8. Accelerator derivation ×8, presentation ×5 (Medium).** `formatShortcut(...currentPlatform())` in ViewMenu:108, EditorChrome:588, EditorContextMenu:248/265, TabContextMenu:103, SettingsMenu:56, ShortcutsDialog:121, ShellMenuRow:84. Presented as `data-shortcut::after`, a real `<span>` (`SettingsMenu.tsx:339`), `aria-keyshortcuts`, `title` tooltip, `<kbd>`.

**B9. Focus-stealing listener (Medium, behavioural).** `EditorContextMenu.tsx:102-110` runs on every `pointerdown` while closed; `openerRef` is never cleared, so after first use every pointerdown anywhere calls `openerRef.current.focus()` (runtime consequence hypothesised, code path confirmed).

**B10. Portal-container lookup ×7 (Low).** `document.querySelector('.application-frame')` at ViewMenu:24, EditorChrome:342/561, SettingsMenu:410/427/573, ShellMenuRow:149.

**B11. Undefined tokens (Low, correctness).** `--menu-trigger-line-height` (`MenuSurface.module.css:43`, `ShellMenuRow.module.css:49`) and `--font-size-sm` (`ShortcutsDialog.module.css:64`) are never defined anywhere.

**B12. Parity route is a second stylesheet (Medium).** `data-parity-shell` selectors: EditorChrome 34, CodeEditor 10, DocumentTabs 8, base 4, AppShell 3 — literal px (`left:210px; top:106px; 190px; 11px`, `DocumentTabs.module.css:234-278`) and Arial glyph fallbacks live in production CSS.

**B13. No Pane / Sidebar components exist (Medium; owner items 4, 6).** Editor and preview panes are two hand-written `<section className={styles.pane}><header className={styles.paneHeader}>` blocks (`EditorView.tsx:489-502` vs `:307-311`). The only sidebar is an empty `<aside>` (`AppShell.tsx:239-243`); the assistant region is a grid track (`--shell-assistant-collapsed-width:0`).

**B14. Inline design values (Low).** `EditorChrome.tsx:500-501` `borderRadius:'12px', gap:'normal'` overrides `.narrowOverflowContent{border-radius:11px}` (`css:398`), making it dead.

## (D) Focus-ring / startup "extra border"

**Confirmed in source:**

1. `base.css:104-107` `*:focus-visible { box-shadow: var(--focus-ring); outline: 0 }` — specificity (0,1,0), applies to popup containers.
2. `main.tsx:3-5` imports `App` (and every CSS module) _before_ `base.css`, so base.css wins ties against `.surface` (`MenuSurface:69`) and `.overflow` (`ShellMenuRow:99`). The `--win-shadow` is **replaced** by `0 0 0 2px var(--app-bg), 0 0 0 4px var(--accent)` (`tokens.css:39`) — a 4px accent ring reading as an extra border. No popup opts out (no `.surface:focus-visible` rule exists).
3. Radix Menu focuses the content element programmatically on open (`node_modules/@radix-ui/react-menu/dist/index.mjs:268`), and the trigger `preventDefault()`s pointerdown when opening (`react-dropdown-menu/dist/index.mjs:77-80`), so the trigger never takes pointer focus. File/About/View content elements therefore carry `:focus` immediately.
4. `theme-bootstrap.js:25-26` sets `data-theme/data-mode` before first paint, so missing tokens at startup are **not** the cause; `applyThemeToRoot` (`theme.ts:50-56`) only rewrites root attributes and remounts nothing.

**Runtime confirmation** is in `focus-ring-probe.json` (Chromium): pointer-opened menus match `:focus-visible` and carry the ring in place of the shadow on fresh load and after pointer interactions; keyboard-opened menus keep the shadow. The owner's native WebKit "disappears after a theme change" observation is consistent with WebKit's modality heuristic for script-focused elements and was not reproduced natively.
