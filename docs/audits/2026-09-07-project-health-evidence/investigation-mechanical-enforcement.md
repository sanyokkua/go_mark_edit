## CGO scope trace (new substantive correction)

Let `W` mean the installed module `/Users/ok/go/pkg/mod/github.com/wailsapp/wails/v2@v2.15.0`.

- `justfile:86–87` runs `CGO_ENABLED=0 go build ./...` without `production`/`dev` tags. On macOS/Linux Wails consequently selects `W/internal/app/app_default_unix.go:1,16–17`, whose CreateApp returns an error explaining that the correct build tags are absent. Compiling that graph does not produce proof of a working native frontend.
- The production implementation is selected by `W/internal/app/app_production.go:1`; it imports desktop at `:9` and constructs it at `:86`. Darwin routing imports its native implementation (`W/internal/frontend/desktop/desktop_darwin.go:9,18–19`), whose `frontend.go:6–16` includes Objective-C CGO flags, links Foundation/Cocoa/WebKit and imports C. Linux frontend also imports C (`W/internal/frontend/desktop/linux/frontend.go:109`).
- Wails’ builder adds production for production/debug modes (`W/pkg/commands/build/base.go:225–226`) and forces `CGO_ENABLED=1` on non-Windows platforms (`:305,327–329`). `just build` invokes that builder via `wails build` (`justfile:20–21`).
- The extra “CGO-free” test reads project strings and rejects explicit `CGO_ENABLED=1` or `import "C"` in project sources (`main_test.go:590–641`). It does not inspect native dependency build selection; it can reject a truthful build setting while silently allowing the dependency to enable CGO.

**Precisely held:** project database code imports modernc SQLite (`internal/db/db.go:20`; version in `go.mod:10`), and the no-tags CGO-disabled build checks the selected non-native graph. **Incompatible with the installed native path:** “one CGO-free Wails v2 desktop binary” on macOS/Linux; the native dependency imports C and its builder enables CGO. **Not established here:** a fresh native build result on every supported OS or a platform-wide deployment matrix.

**Disposition:** explicitly reconcile constitution:80 and architecture/rules.md:533–547 to the intended boundary: pure-Go SQLite/application backend versus the native Wails host/toolchain. Keep a correctly named pure-Go backend/SQLite build check and a separate real native Build stage. This is an authority correction to propose, not a silent weakening performed in this audit. No builds were run to make this determination.
