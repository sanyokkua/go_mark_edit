# Tasks: Codebase Refactoring

**Input**: `specs/004-codebase-refactoring/{spec.md,plan.md,research.md,data-model.md,quickstart.md}`,
the seven contracts and `baseline-record.schema.json` under `contracts/`, and the constitution
v2.0.0.

**Prerequisites**: plan.md (task groups G1–G10, Story 1 regression table, white-box list W1–W3,
E2E lever table, walkthrough steps, per-suite coverage tables, known-issues table, requirement
coverage table), spec.md (FR-001…FR-084, SC-001…SC-015, US1–US7, edge cases).

**Organization**: phases follow the plan's binding group order G1 → G10. That order overrides
user-story priority order: a story's tasks appear in the phase whose group owns them, and each phase
names the stories it serves. Phase 1 is G1 (scripts, serves US5), Phase 2 is G2 (baseline, reformat,
archive worktree), Phases 3–9 are G3–G9 with story labels, Phase 10 is G10 (close, no story label).

## Rules for every task

- No task ID, requirement ID, `Proves:` anchor or story label in any test file, test title or test
  comment (FR-030, FR-080). The requirement mapping lives only in this file and `plan.md`. Every test
  title is a sentence describing the behaviour.
- Nothing is built that `spec.md`, `plan.md`, the contracts or `research.md` do not state. A silent
  or ambiguous point is raised with a recommended default, never resolved in code.
- A task is done when its named evidence is green and `scripts/verify` (or every stage the task can
  affect) is green against the baseline of T002.
- Never `--no-verify`; never merge into `app_version_1_codebase` or `master` (the owner does).
- `frontend/wailsjs/**` is generator-owned: regenerated by `scripts/build`, never hand-edited.
- Spec Kit files stay untouched: `.specify/**`, the `speckit-*` skills under `.claude/skills` and
  `.agents/skills`, and the extensions.
- Branching: a task big enough for several commits uses `feature/004-codebase-refactoring-<slug>`
  and is squash-merged back; a small task commits straight to `feature/004-codebase-refactoring`.
  Conventional Commits.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no unfinished dependency)
- **[Story]**: the user story the task serves (US1…US7); absent in Phases 1, 2 and 10
- Every description names the primary file path
