# Contract: bridge requests, bounds and outcomes

Requirements: FR-019, FR-020, FR-021, FR-052, FR-055, SC-014. Owners: `internal/bridge` (Go, leaf
package importing only `internal/apperr`) and `frontend/src/logic/adapter/` (the only importer of
the generated bindings).

## Request identity

Every bound method takes `bridge.Request` as its first parameter:

```go
type Request struct { ID string `json:"id"` }
```

The 35 existing bindings (`AppModelHandler` ×24, `SettingsHandler` ×7, `ApplicationHandler` ×4)
and the one new binding `OpenPreviewLink` all gain it; the generated `frontend/wailsjs` bindings are
regenerated by `scripts/build`. An empty ID is refused with a `validation` failure. The adapter mints
one UUID per command invocation (`crypto.randomUUID()`), and a Retry re-sends the _same_ ID with the
same arguments.

## Handler shape (checked by `tools/archlint`)

```go
func (h *AppModelHandler) Save(request bridge.Request, documentID string, revision uint64) (result apperr.WriteResult) {
    defer bridge.Guard(&result)                       // one shared recover; a panic becomes an `internal` failure
    return bridge.Once(h.outcomes, request, func() apperr.WriteResult { … })  // join in-flight / answer from cache
}
```

Rules: returns exactly one `apperr.*Result`; takes no `context.Context`; named result; the first
statement is `defer bridge.Guard(&result)`; the handler calls its service only. All result envelopes
embed `apperr.Failure` (category, subject, message, remediation, id) so one constructor,
`bridge.Fail(...)`, builds every classified failure; no hand-written recover block or error wrapper
remains (FR-052).

## Outcome cache (`bridge.OutcomeCache`)

| Rule           | Value                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| Key            | `Request.ID`                                                                                           |
| Retention      | 60 seconds after completion                                                                            |
| Capacity       | 256 completed outcomes; the oldest is evicted first                                                    |
| In flight      | a second call with a running ID waits for and returns the running call's outcome (no second execution) |
| After eviction | the call is a fresh command                                                                            |
| Scope          | one cache per process, shared by the three handlers                                                    |

## Pacing (frontend adapter)

| Command                                                                                                                                                                                                                                                                                   | Pacing                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `OpenDocument`, `SaveAs`, `Save` when the active document is untitled, `ResolveClosePlan`                                                                                                                                                                                                 | user-paced: no bound (a native dialog is open)                                             |
| every other command (`GetState`, `UpdateBuffer`, `Save` of a titled document, `SetDocView`, `SetUILayout`, `CloseDocument`, `PrepareClose`, `ExecuteClosePlan`, conflict commands, settings commands, `WindowReady`, `RetryStartup`, `AuthorizeQuit`, `CancelQuit`, `OpenPreviewLink`, …) | bounded: 10 seconds, counted from the call, active only once `bootstrapStatus === 'ready'` |

Before ready, the startup steps have their own 10-second rule (FR-015): a step that does not answer
is reported by the startup-failure screen as "did not answer within 10 seconds", not by a notice.

## Stuck notice

- One notice per request ID in the notification surface, with **Retry** and **Cancel**; editing continues.
- A result that arrives after the notice is applied and the notice is withdrawn.
- **Retry** re-sends the same request; the backend answers from the cache or the running call; the
  result is applied exactly once.
- **Cancel** dismisses the notice and stops waiting; the command is not aborted; a late result is
  applied silently.
- Two stuck requests → two notices, each withdrawing on its own result.

Timing acceptance (SC-014): the notice appears within 1 second of the 10-second bound; a Retry more
than 60 seconds after completion runs as a fresh command.

## Events

One Go constant file `internal/bridge/events.go` and one TypeScript module
`frontend/src/logic/adapter/events.ts` hold the only copies of the event names:

| Event                         | Payload                                           | Emitted by                                                                                             |
| ----------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `state:patch`                 | `apperr.AppStatePatch` (revisioned, content-free) | the publication path of the lifecycle owner                                                            |
| `state:error`                 | `apperr.WireError` (classified, cause-free)       | async failures: autosave, layout persistence                                                           |
| `application:close-requested` | `{ id }`                                          | the shutdown owner, once per request; the pending request is also visible in `GetState().pendingClose` |

The emitter adapter (`RuntimeEmitter`) lives in `internal/application` and is passed to the model
through `WithEmitter` (FR-055); `internal/appmodel` imports neither the Wails runtime nor
`internal/bootstrap`; the application version reaches the model through `WithVersion`.

## Adapter obligations

- Only `frontend/src/logic/adapter/**` imports `wailsjs/**` (lint rule).
- Every binding is called through one wrapper that checks arity, attaches the request ID, applies the
  pacing rule, unwraps the envelope once, and reports a failure once through the notification owner.
- The adapter keeps no English strings; the recovery message currently hard-coded in
  `appModelAdapter.ts` moves to the catalogue.
