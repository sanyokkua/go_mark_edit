# Quickstart: validating Rich Markdown Authoring

Runnable checks that prove the feature end to end. Scenario ids (`US1-4` is User Story 1, scenario 4)
refer to the acceptance scenarios in [spec.md](./spec.md); the expected outcome of each walk row is the
cited scenario's **Then** clause. Contract details are in [contracts/](./contracts/) and
[data-model.md](./data-model.md).

## Prerequisites

```bash
scripts/build setup --with-browser   # Go, Node, Wails CLI, Playwright browser
scripts/baseline                     # once, by the first implementation task, before its first edit
```

## Fixtures

Committed under `frontend/tests/fixtures/`, which `scripts/format` and `frontend/.prettierignore` exclude from
formatting (plan, Test placement). Rule L22 scans every text file under `frontend/tests/`, so no fixture line
may match `/\bT\d{3}\b|FR-|SC-|STORY-|Proves:/`; `FR-`, `SC-`, `STORY-` and `Proves:` match anywhere in a
line, including inside a longer word.

- `reference-document.md`: every construct of FR-RN-003 and FR-RN-004, one invalid formula, one invalid
  Mermaid block, a Go block, an unknown-language block, the currency paragraph, two `## Notes` headings,
  `## Über uns` and `## Getting Started` with a link to it, and hostile HTML: each of the 29 elements FR-RN-008
  removes with its contents (those that can hold text hold visible text; the void elements `embed`, `link`, `meta`, `base` and the parser-ignored `head` and `frame` appear without text and are asserted only to leave no element), an unknown element holding text, an `onclick` and a
  `style` attribute, and `javascript:` and `data:` addresses in several spellings. The hostile HTML comes last,
  with `plaintext` as the final element, because an HTML parser treats everything after `<plaintext>` as text.
- `messy-document.md`: `*` and `+` bullets, `*` emphasis, Setext headings, an unpadded table, blank-line
  runs, trailing spaces, a two-space hard break, `foo*bar*baz`, a tight list, adjacent `-` and `*` lists,
  `1. 1. 1.` and `1. 2. 3.` lists, fenced and indented code with trailing spaces.
- `three-findings.md`: with the default preferences, exactly three lint findings from three different rules: one
  `*` bullet item (`ul-marker`), one prose line ending in a single space (`trailing-space`) and one fenced block
  without a language (`fence-language`); it has one level-1 heading, no blank-line runs and a final newline.
- `tidy-corpus/`: at least 30 varied documents for idempotence and render equivalence (SC-003).
- `link-tree/`: the folder to open, with `docs/a.md` (links to every target below), `docs/sub/b.md` with
  `## Setup`, `c.md`, `.hidden/d.md`, `report.pdf`; plus `link-outside.md` next to the folder.

Generated by the tests into their temporary directory (not committed):

- a 3 MiB editable document, rich in lists and tables (US2-13, US2-17);
- a 512 KiB document of deeply nested lists, whose Format run lasts longer than one second (US2-19);
- a document with 1,500 lint findings (US2-9, SC-004) and one with 12,000 findings (US2-18);
- a read-only document: a small file containing a lone carriage return, which opens read-only (US2-12);
- a 40-document setup: 40 small documents opened before the run, plus a link to a 41st (US3-8);
- a document with 51 Mermaid blocks and one formula longer than 10,000 characters (US1-11);
- a 100 KB document with 10 Mermaid diagrams (SC-002).

For the manual walk, write the generated documents to a scratch folder with the same generator.

## Fast checks while working

```bash
scripts/verify lint
scripts/format --check
scripts/test unit
scripts/test integration
```

Unit and integration tests cover the pure logic (classifier, pipeline, headings, math, tidy rules,
operation slot). Real Monaco, Mermaid, KaTeX and the folder tree are proven in E2E.

## Full verification

```bash
scripts/verify                                  # Lint, Format, Build, Unit, Integration, E2E
scripts/baseline --compare                      # at feature close
node tools/lint/bundle-scan.mjs frontend/dist   # after a production build; must report ok
```

Expected: six stages green against the recorded baseline; the bundle scan reports no remote asset URL;
the build shows Mermaid and KaTeX as lazy chunks and KaTeX fonts as woff2 only. The Linux push workflow runs
`scripts/verify --skip e2e`; the macOS release workflow runs the full verification, E2E included. E2E
performance has been measured on macOS arm64 only and E2E on Linux is unverified; record the platform with the
result.
